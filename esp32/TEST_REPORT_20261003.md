# VoiceShell × Muse 文本桥接原型：实测记录

日期：2026-10-03。状态：三轮文本收发闭环通过，非产品发布验收。

## 实际跑通的链路

电脑测试程序 → USB → 已配对 ESP32-S3 → Muse → voiceshell.reply 设备工具 → ESP32-S3 → USB → 电脑测试程序。

发送通过官方 SDK 所用的 POST /chat/stream。回复通过新增的设备工具回传，不读取账户全部聊天记录，不导出设备凭证。板子仅暂存当前请求的回复文本，最多 1024 UTF-8 字节；测试程序为每轮生成新的关联编号。

## 真机结果

| 项目 | 结果 |
|---|---|
| 应用区烧录 | 校验通过，未写 NVS，原配对保留 |
| 启动与重连 | 无 panic；Wi-Fi 和 Muse WebSocket 恢复连接 |
| 第一轮中文确认 | 电脑实际收到“已收到，中文回传成功” |
| 第二轮短回答 | 电脑实际收到“第二轮：42”，整个测试进程约 5.7 秒 |
| 第三轮完整中文句子 | 电脑实际收到“这只是文本桥接原型，暂不支持耳机语音播放。”，整个测试进程约 3.5 秒 |
| 回复关联 | 三轮使用不同编号，只接受本轮编号匹配的回复 |
| 客户端单元测试 | 10 项通过，包括错编号忽略、单次发送、错误不自动重发 |
| 相关上游测试 | 日志 6 项、串口聊天 11 项通过；并非全套测试通过 |

设备凭证访问 GET /chat/history 返回 403，明确原因为 `path not allowed for device token`。没有绕过该限制，也没有冒用手机应用身份。新回传方式依赖 Muse 正确调用设备工具，不能保证每次模型响应都调用。
